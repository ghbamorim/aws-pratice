## Requisitos — AWS Lab

### 1. Infraestrutura

1. Toda a infraestrutura provisionada com Terraform.
2. Utilizar exclusivamente recursos elegíveis ao AWS Free Tier, priorizando custo zero.
3. EC2 única executando Docker Compose.
4. RDS PostgreSQL com recursos mínimos, sem backups e sem Multi-AZ.
5. ECR armazenando as imagens Docker do frontend e backend.
6. Terraform State local, fora da infraestrutura AWS.

### 2. Aplicação

7. Frontend React servido pelo Nginx dentro do container.
8. Backend FastAPI em container separado.
9. Nginx encaminhando `/api` para o backend.
10. Acesso exclusivamente HTTP, porta 80.
11. Migrations do Alembic executadas automaticamente.

### 3. Deploy

12. `terraform apply` cria toda a infraestrutura, inclusive ECR vazio.
13. GitHub Release dispara GitHub Actions.
14. GitHub Actions constrói e publica as duas imagens na ECR.
15. Deploy automático na EC2 após publicação das imagens.
16. DuckDNS atualizado automaticamente via API, utilizando token secreto.
17. Domínio: `aws-lab-ghbamorim.duckdns.org`.

### 4. Destruição e recriação

18. `terraform destroy` remove todos os recursos AWS, inclusive ECR e imagens.
19. Nenhuma dependência de recursos AWS preservados.
20. Recriação funcional após `terraform apply` e novo GitHub Release.
21. Processo reproduzível, sem configurações manuais na AWS.

### 5. Confiabilidade

22. Verificações de prontidão com retry e timeout.
23. AWS CLI Waiters quando aplicáveis.
24. Docker healthchecks e controle de dependências.
25. Falhas explícitas, com logs para diagnóstico.
26. Não utilizar `sleep` fixo como garantia de prontidão.

### 6. Regras operacionais

27. Sempre fornecer `terraform apply`, nunca `terraform plan`.
28. Comandos de investigação devem descobrir identificadores e executar a operação em um único comando.
29. Evitar etapas manuais e comandos que exijam copiar IDs.
30. Prioridade máxima: destruir, recriar e colocar todo o ambiente em funcionamento de maneira previsível.
